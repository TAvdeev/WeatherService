# Запуск приложения Погода и климат на Kali Linux

В результате вы запустите четыре контейнера одной командой, откроете сайт, получите настоящую погоду и проверите, что запросы сохраняются в базе данных. Все команды ниже вводятся **в терминале Kali Linux**, а адреса сайтов — в браузере Kali.

## 1. Что потребуется

- Обычная установленная Kali Linux или Kali в виртуальной машине с работающим `systemd`. Инструкция не предназначена для Kali, запущенной внутри другого Docker-контейнера, или Android NetHunter.
- 64-разрядный процессор `x86_64` (amd64) или `aarch64` (arm64). Это архитектуры, для которых выбранные образы и зависимости рассчитаны в этом проекте. Проверка: `uname -m`.
- Практический ориентир для виртуальной машины: 2 ядра, 4 ГБ ОЗУ, не менее 5 ГБ свободного места сверх установленной Kali. Это рекомендация для комфортной работы, а не измеренный минимум.
- Интернет для скачивания образов, Python-зависимостей и получения новой погоды. Уже сохранённая история работает без доступа к погодному источнику.
- Права администратора через `sudo`. Пароль вводится вслепую: символы и звёздочки в терминале не появляются. Нажмите Enter после ввода.
- Современный Firefox/Chromium. Node.js, npm, Python-пакеты и PostgreSQL на саму Kali для запуска приложения устанавливать не нужно: они находятся в контейнерах. Python 3 используется только для дополнительной проверки.

Docker Engine запускает контейнеры, а Docker Compose читает `docker-compose.yml` и управляет всем приложением сразу. Docker Desktop для Kali не требуется.

## 2. Установите Docker и Compose

Если Docker уже установлен, сначала выполните:

```bash
sudo docker --version
sudo docker compose version
```

Если обе команды выводят версии, переходите к разделу 3. Нужна именно команда `docker compose` с пробелом. Устаревший Compose V1 с командой `docker-compose` не используется.

Для чистой Kali выполните по очереди:

```bash
sudo apt update
sudo apt install -y docker.io docker-compose unzip curl python3 git
sudo systemctl enable --now docker
sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
```

В современных репозиториях Kali пакет `docker-compose` предоставляет Compose с командой `docker compose`. После `hello-world` ожидается сообщение `Hello from Docker!`. Это проверка Docker, а не компонент приложения: временный контейнер автоматически удаляется. Официальная инструкция Kali использует пакет `docker.io`; пакет с именем просто `docker` для этой задачи не подходит.

Если система не находит пакет или `docker compose version` не работает, проверьте источники обновлений по [официальной документации Kali](https://www.kali.org/docs/general-use/kali-linux-sources-list-repositories/). Не добавляйте случайные репозитории Ubuntu. Альтернатива — установка Docker Engine и пакета `docker-compose-plugin` из официального репозитория Docker для Debian по [инструкции Docker](https://docs.docker.com/engine/install/debian/) с учётом [примечаний для Kali](https://www.kali.org/docs/containers/installing-docker-on-kali/). Не смешивайте установку `docker.io` и `docker-ce`: при уже настроенном Docker используйте его существующий способ установки.

Все дальнейшие команды приведены с `sudo`, поэтому добавлять пользователя в группу Docker необязательно.

## 3. Перенесите и распакуйте проект

Сохраните `weather-compose.zip` в домашнюю папку пользователя **в Kali**. Если работаете в виртуальной машине, перенесите архив через общую папку, перетаскивание файлов или USB. Архив, оставшийся на macOS, сам по себе в Kali не появится.

Откройте файловый менеджер Kali, найдите архив и при необходимости переместите его в домашнюю папку. Затем откройте терминал и выполните:

```bash
cd ~
unzip weather-compose.zip
cd weather-compose
ls -a
```

Вы должны увидеть `docker-compose.yml`, `README.md`, папки `frontend`, `backend`, `web-service`, `db`, `docs`, `scripts` и `tests`. Не запускайте команду Compose из родительской папки. `cd` меняет текущую папку, `ls` показывает её содержимое. Если вы распаковали архив через файловый менеджер, перейдите в получившуюся папку через «Открыть терминал здесь» и пропустите повторную распаковку.

В проекте уже есть учебные настройки по умолчанию. Копировать `.env.example` для первого запуска не нужно, получать ключ погодного API тоже не нужно.

## 4. Запустите приложение

В папке с `docker-compose.yml`:

```bash
sudo docker compose config -q
sudo docker compose up --build -d
sudo docker compose ps
```

Первая команда проверяет конфигурацию; при успехе ничего не печатает. Вторая скачивает базовые образы, собирает три прикладных образа, создаёт сеть, volume и запускает все четыре сервиса. Первый запуск может занять несколько минут, особенно при медленном интернете. Параметр `-d` означает работу в фоне: терминал можно закрыть.

`ps` должен показать четыре сервиса: `frontend`, `backend`, `db`, `web-service`. После завершения стартовых проверок у каждого ожидается состояние `Up` и `healthy`. Если видите `health: starting`, подождите несколько секунд и повторите `ps`. Backend ждёт готовности БД и погодного сервиса, Frontend — готовности Backend.

Заданный преподавателем вариант запуска тоже поддерживается:

```bash
sudo docker compose up --build
```

При таком запуске терминал показывает логи. Нажатие Ctrl+C останавливает контейнеры. Для обычной работы удобнее вариант с `-d`.

## 5. Откройте сайт

Запустите браузер **внутри Kali** и откройте:

```text
http://localhost:8080
```

Введите адрес именно с `http://`, а не `https://`. Дополнительно доступны страницы:

| Назначение | Адрес |
| --- | --- |
| Backend и ссылки на его API | http://localhost:8000 |
| Интерактивное API Backend | http://localhost:8000/docs |
| Погодный веб-сервис | http://localhost:8001 |
| Интерактивное API веб-сервиса | http://localhost:8001/docs |

Swagger на `/docs` загружает своё оформление из CDN; для него тоже может понадобиться интернет. `/openapi.json`, страницы сервисов и основной сайт не требуют CDN.

`localhost` означает компьютер, на котором открыт браузер. При открытии адреса в браузере macOS он указывает на macOS, а не на виртуальную Kali. Для этой инструкции используйте браузер Kali. Порты намеренно привязаны к `127.0.0.1`: другие компьютеры локальной сети к приложению не подключаются.

## 6. Как пользоваться

1. Введите город, например `Москва`, и нажмите **«Получить погоду»**. Можно использовать быстрые кнопки городов.
2. Если обнаружено несколько мест с таким названием, выберите нужную страну и регион из списка. Например, Москва есть и в России, и в США.
3. Дождитесь карточки с температурой, ощущаемой температурой, влажностью, ветром и временем данных. Успешный запрос уже записан в БД. Ошибка поиска или сети не создаёт запись с выдуманными значениями.
4. Нажмите **«Загрузить историю»**. Это отдельное чтение PostgreSQL через Backend. При первом запуске там уже есть две записи с меткой **«Учебный пример»**: они нужны для демонстрации автоматической инициализации. Их числа не получены от Open-Meteo.
5. В истории нажмите **«Заметка»**, введите наблюдение и сохраните. Это изменение записи в БД.
6. Кнопка **«Удалить»** удаляет выбранную запись после подтверждения. Удаление необратимо, другие запросы не затрагиваются.
7. Поле «Поиск в истории» отбирает записи по части названия города. Для сброса очистите поле и нажмите «Найти». При более чем десяти записях используйте «Далее» и «Назад».

Повторное получение погоды создаёт новый запрос в истории, даже если модель ещё не обновилась. Время данных и время запроса хранятся отдельно. В интерфейсе оба показаны в часовом поясе браузера. На странице всегда видно, что источник — Open-Meteo; географические данные — GeoNames.

## 7. Проверьте работу и сохранность БД

Из папки проекта:

```bash
python3 scripts/smoke.py
```

Проверка проходит через пользовательский порт 8080, запрашивает настоящий Open-Meteo, записывает результат, читает его, изменяет заметку и удаляет только собственную проверочную запись. Ожидаемая последняя строка начинается с `УСПЕХ`. Если источник недоступен, исправьте доступ к интернету и повторите позже; это не повод подменять погоду учебными значениями.

Проверка сохранности вручную:

1. Получите погоду в интерфейсе и добавьте заметку `Проверка сохранения`.
2. Запомните город и время запроса.
3. В терминале выполните:

```bash
sudo docker compose down
sudo docker compose up -d
sudo docker compose ps
```

4. Откройте сайт, нажмите «Загрузить историю». Запрос и заметка должны остаться. Это обеспечивается именованным volume `weather-data`.

Чтобы увидеть строки непосредственно в PostgreSQL:

```bash
sudo docker compose exec db psql -U weather -d weather -c "SELECT id, city, temperature, requested_at, note, is_demo FROM weather_requests ORDER BY id DESC LIMIT 10;"
```

Показать структуру таблицы:

```bash
sudo docker compose exec db psql -U weather -d weather -c '\d weather_requests'
```

Выходить из интерактивной оболочки БД здесь не нужно: параметр `-c` выполняет команду и возвращает в терминал.

## 8. Остановка и следующий запуск

Остановить и удалить контейнеры, сохранив историю:

```bash
sudo docker compose down
```

Запустить снова, без повторной сборки:

```bash
sudo docker compose up -d
```

После изменения исходного кода:

```bash
sudo docker compose up --build -d
```

После перезагрузки Kali служба Docker запускается автоматически, а контейнеры используют `restart: unless-stopped`. Если вы остановили проект вручную, запустите его снова через `up -d`.

**Полный сброс БД** нужен только если вы хотите удалить всю историю и снова получить начальные учебные записи:

```bash
sudo docker compose down -v
sudo docker compose up --build -d
```

`-v` удаляет volume с данными. Не используйте его для обычной остановки. `init.sql` выполняется только при первой инициализации пустой БД; редактирование SQL-файла не изменит уже существующий volume автоматически.

## 9. Настройки и занятые порты

Если порт 8080, 8000 или 8001 занят, создайте локальный файл настроек:

```bash
cp .env.example .env
nano .env
```

Например, измените `FRONTEND_PORT=8080` на `FRONTEND_PORT=8088`. В nano нажмите Ctrl+O, Enter для сохранения, затем Ctrl+X. Примените настройки:

```bash
sudo docker compose up --build -d
```

Сайт теперь будет на `http://localhost:8088`. Для проверки используйте:

```bash
python3 scripts/smoke.py http://localhost:8088
```

`BACKEND_PORT` и `WEB_SERVICE_PORT` меняют только внешние адреса, внутренние подключения продолжают работать. `DB_PASSWORD` — учебный пароль БД; `.env` исключён из Git. Если вы меняете пароль после создания БД, одного изменения `.env` недостаточно: PostgreSQL сохраняет пароль в volume. Для этого учебного проекта проще оставить пароль по умолчанию или выбрать свой **до первого запуска**. Полный сброс данных описан выше и удаляет историю.

## 10. Если что-то не работает

Сначала проверьте:

```bash
sudo docker compose ps
sudo docker compose logs --tail=100 frontend backend db web-service
```

| Сообщение или симптом | Что сделать |
| --- | --- |
| `no configuration file provided` | Перейдите командой `cd` в папку с `docker-compose.yml`. |
| `Cannot connect to the Docker daemon` | Выполните `sudo systemctl start docker`, затем повторите запуск. |
| `permission denied` при обращении к Docker | Используйте `sudo docker ...`, как в примерах. |
| `docker: 'compose' is not a docker command` | Проверьте установку современного Compose в разделе 2. |
| `address already in use` / `port is already allocated` | Измените соответствующий порт через `.env`, раздел 9. |
| Ошибка скачивания образа или Python-пакетов | Проверьте интернет и правильность времени Kali, затем повторите `up --build -d`. |
| Сайт не открывается с macOS | Откройте его в браузере Kali; `localhost` у каждой ОС свой. |
| `502`, `503`, `504` при получении погоды | Посмотрите логи `web-service`; проверьте доступ к Open-Meteo, повторите позже. История доступна отдельно. |
| Город не найден | Проверьте написание, попробуйте латиницу или уточнение страны. Не все маленькие населённые пункты есть в GeoNames. |
| База `unhealthy`, ошибка аутентификации | Проверьте логи `db` и не менялся ли пароль при существующем volume. |
| Учебные записи не появились повторно | Это нормально при существующей БД: `init.sql` не выполняется заново. |

Проверка связи с источником **из контейнера**:

```bash
sudo docker compose exec web-service python -c "import httpx; r=httpx.get('https://geocoding-api.open-meteo.com/v1/search', params={'name':'Moscow','count':1}, timeout=15); print(r.status_code); print(r.text[:500])"
```

Для просмотра логов в реальном времени выполните `sudo docker compose logs -f`. Ctrl+C прекращает просмотр, но не останавливает работающие в фоне контейнеры.

## 11. Что помнить о проверках

Приложение разработано для запуска в Linux-контейнерах на Kali. В среде подготовки Docker отсутствовал, поэтому полный контейнерный запуск ещё нужно подтвердить на вашей Kali командами разделов 4 и 7. В [VERIFICATION.md](VERIFICATION.md) перечислены фактически выполненные проверки без подмены их результатами запуска Docker.

Официальные источники инструкции: [Docker на Kali](https://www.kali.org/docs/containers/installing-docker-on-kali/), [пакет Compose в Kali](https://pkg.kali.org/pkg/docker-compose), [порядок запуска Compose](https://docs.docker.com/compose/how-tos/startup-order/), [API Open-Meteo](https://open-meteo.com/en/docs).
