# Соответствие заданию и результаты проверок

## Требования задания

| Требование | Реализация |
| --- | --- |
| Четыре независимых контейнера | `frontend`, `backend`, `db`, `web-service` в корневом `docker-compose.yml`. |
| Общая стандартная bridge-сеть | `weather-net`, `driver: bridge`. |
| Две функциональные кнопки Frontend | «Получить погоду» обращается к погодному сервису через Backend; «Загрузить историю» читает БД через Backend. |
| Удобное отображение данных | Карточка погоды, таблица истории, поиск и страницы. Мобильная раскладка. |
| Backend REST API | FastAPI, описание `/docs` и `/openapi.json`. |
| CRUD в БД | Создание погодного запроса, список и отдельная запись, редактирование заметки, удаление записи. |
| СУБД | PostgreSQL 17. |
| Автоматическая инициализация | `db/init.sql`: таблица, ограничения, индексы, две помеченные учебные записи. |
| Специализированный веб-сервис | Отдельный Python/FastAPI-сервис с интеграцией официального API Open-Meteo. |
| Вариант «Погода и климат» | Текущая погода по названию города, история запросов. |
| Указание источника на сайте | Open-Meteo, GeoNames, ссылки, лицензия и пояснение модельных данных. |
| Dockerfile для сборки | Собственные Dockerfile у Frontend, Backend и web-service. БД использует официальный образ. |
| Один Compose-файл | Все четыре сервиса запускаются одной командой; дополнительных Compose-файлов нет. |
| Переменные окружения | Подключения к БД и веб-сервису, адреса провайдеров, настраиваемые внешние порты, `.env.example`. |
| Проброс портов | Локальные 8080, 8000 и 8001. БД доступна внутри сети. |
| Порядок запуска и готовность | `depends_on` с `service_healthy`, healthcheck у БД и прикладных компонентов. |
| Сохранность данных | Именованный volume `weather-data`. |
| README и `.gitignore` | В корне проекта; `.env`, кэши, окружения и сборочные файлы исключены. |
| Инструкция для Kali Linux | `docs/KALI_LINUX.md`: установка, распаковка, запуск, проверка, работа, остановка, устранение ошибок и сдача. |

## Фактически выполнено при подготовке

Проверки выполнены 11 октября 2026 года на macOS, в отдельном временном окружении Python 3.12. Приложение предназначено для Linux-контейнеров; эти проверки не означают запуск Docker на Kali.

- **Конфигурация Compose:** официальный Docker Compose v2.39.4 успешно выполнил `config --quiet` над итоговым `docker-compose.yml`. Дополнительно проверены четыре имени сервисов, сеть, Dockerfile, зависимости и volume.
- **Синтаксис:** Python-файлы компилируются; `app.js` прошёл проверку синтаксиса Node.js.
- **Настоящий источник:** официальный Open-Meteo вернул список городов и реальные текущие условия для Москвы, включая выбранный ID населённого пункта, температуру, влажность, ветер и UTC-время данных.
- **Настоящая БД:** временная PostgreSQL 17 инициализирована именно поставляемым `db/init.sql`. Созданы обе учебные записи. Проверены создание, чтение, изменение, удаление, фильтры, параметры SQL и пагинация.
- **18 автоматических тестов:** все прошли, включая интеграционный сценарий с настоящей PostgreSQL. В проверках ошибок моделировались тайм-аут, ограничение частоты, неверный JSON, неизвестный город, недоступность БД, неверный ввод и слишком длинная заметка.
- **Сквозной HTTP-сценарий:** `scripts/smoke.py` прошёл через локальный HTTP-прокси, настоящие процессы Backend/web-service, официальный Open-Meteo и PostgreSQL. Временный прокси использовался только для проверки без Docker; в поставляемом проекте эту роль выполняет Nginx.
- **Браузер:** в Google Chrome проверены обе основные кнопки, выбор города, настоящая карточка погоды, история, сохранение заметки, удаление с подтверждением и пустой результат поиска. Текст с HTML-тегами отображается как текст, не выполняется как скрипт. Ошибок JavaScript не зафиксировано.
- **Внешний вид:** просмотрены снимки страницы на широком экране и при ширине 390 px. В мобильной раскладке нет горизонтального переполнения страницы; таблица имеет собственную прокрутку.

## Что нужно подтвердить на Kali

В среде подготовки не установлен Docker Engine, поэтому **сборка Dockerfile, запуск четырёх контейнеров, работа Nginx в контейнере и сохранность Docker volume при `down`/`up` не подтверждены исполнением**. Нельзя считать эти пункты проверенными только на основании тестов Python.

Перед сдачей выполните в Kali:

```bash
sudo docker compose config -q
sudo docker compose up --build -d
sudo docker compose ps
python3 scripts/smoke.py
```

Ожидается четыре работающих сервиса с успешными healthcheck и строка `УСПЕХ` от проверки. Затем проверьте сохранность записи и заметки после обычного `down` / `up -d` по инструкции. Если возникает ошибка, используйте раздел устранения проблем и сохраните вывод `docker compose logs --tail=100`.

## Дополнительный запуск тестов без контейнеров

Это необязательно для обычного запуска. Для разработчика в отдельном окружении Python 3.12, из корня проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
python -m unittest discover -s tests -v
```

Без специальной настройки тестовой PostgreSQL 17 проверок выполняются, один интеграционный сценарий пропускается. Для него переменная `WEATHER_TEST_DATABASE=1` включает доступ к отдельной тестовой БД, инициализированной `db/init.sql`; адрес задаётся `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`. Сценарий создаёт свои записи и очищает их. В предоставленной Compose-конфигурации порт PostgreSQL наружу не опубликован.
